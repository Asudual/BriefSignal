# 文章四维评分

## 触发与路由

用户说以下词时进入本 skill：**评分、打分、筛文章、荐读评分、定级、这篇文章值不值得看**

路由逻辑：
- 用户提供**文章标题+正文** → 单篇评分
- 用户提供**多个链接/标题** → 批量评分+筛选
- 用户说"找几篇好文章" → 先搜索再评分筛选
- 用户只说"评分"无输入 → 追问"要评哪篇文章？发我标题和正文"

**不要因触发词模糊就等待用户重复指令。直接进入流程搜索或追问。**

## 执行流程

### 1. 先跑排除规则

满足**任一**条件，直接判 C 级不推送，一句话说明原因，跳过后续评分：

- 广告/软文（含知识星球、付费社群、课程引流、优惠券）
- 纯资讯快讯，无分析（如"XX公司发布了XX"一句带过）
- 标题与正文严重不符
- 正文 < 200 字
- AI 生成痕迹明显的搬运内容（如"作为AI语言模型"等）

### 2. 确定文章类型，微调权重

读完整篇文章后，先判定文章类型：

| 类型 | 深度 | 原创 | 实操 | 标题 | 说明 |
|------|------|------|------|------|------|
| 技术教程/实战 | 35% | 25% | 25% | 15% | 默认 |
| 行业综述/趋势 | 40% | 30% | 15% | 15% | 降低实操权重 |
| 论文解读 | 35% | 25% | 20% | 20% | 解读的原创在理解深度 |
| 工具/产品推荐 | 20% | 25% | 40% | 15% | 实操是重点 |
| 观点/评论 | 30% | 40% | 10% | 20% | 原创观点是核心 |

如文章类型模糊或跨类，用默认权重（35/25/25/15）。
**判断文章类型时附一句说明，如"类型：技术教程 → 注重实操和代码质量"**

### 3. 四维打分

每个维度给 **0-100 的整数分 + 一句话依据（不超过30字）**。
依据不能是复制原文片段，必须是你自己的判断。

**一、深度（是否"有货"）**

```
90-100  论文/技术报告级，论证链完整，有数据/实验/源码支撑
70-89   技术分析扎实，有案例和引用，逻辑闭环
50-69   有技术讨论但停留在概述，缺深入分析
30-49   泛泛而谈，信息密度低
0-29    纯水文
```

**二、原创性（是否"自己的"）**

```
90-100  一手经验、独到方法、个人深度洞察
70-89   有独立观点和整理分析，非简单翻译拼凑
50-69   信息整合尚可，但缺个人视角
30-49   明显搬运/翻译/拼凑
0-29    纯转载或AI水文
```

**三、实操性（能否"直接用"）**

```
90-100  完整可复现代码/配置/步骤
70-89   有具体操作指南或工具推荐
50-69   方法论层面，缺具体步骤
30-49   纯概念讨论
0-29    完全不落地
```

**四、标题质量（是否"说人话"）**

```
90-100  精准概括，信息密度高，不夸张
70-89   与内容匹配但偏平淡
50-69   轻度标题党或概括不准
30-49   明显标题党/夸大/误导
0-29    文不对题
```

### 4. 算总分

```
总分 = 深度×W1 + 原创性×W2 + 实操性×W3 + 标题质量×W4
（W1-W4 为第2步确定的具体权重，保留一位小数）
```

### 5. 定等级

- **A 级 ≥75** → 优先推送，🔥 标签
- **B 级 60-74** → 备选，🔔 标签
- **C 级 <60** → 不推送

### 6. 输出格式

**单篇评分输出：**

```
📄 [文章标题]
类型: [技术教程/行业综述/...]

深度   85/100 · 有Benchmark数据和架构图支撑，论证完整
原创性 70/100 · 整合多家方案但缺少自己的实测对比
实操性 90/100 · 提供完整的Docker部署脚本和配置文件
标题质量 80/100 · 准确概括，但偏技术术语堆砌
---
总分 80.5 | A级 🔥
```

**批量评分输出（重点）：**

先输出筛选汇总，再按总分降序列出每篇完整的评分卡片，最后输出可直接复制的推送文案：

```
📊 共评 X 篇
A级 X 篇 → 推送
B级 X 篇 → 备选（不推）
C级 X 篇 → 已排除

——— A级（按总分降序） ———

📄 [标题1]
深度   XX  原创   XX  实操   XX  标题  XX
总分   XX.X | A级 🔥

📄 [标题2]
...

——— B级（按总分降序） ———

...

📌 推荐摘要（可直接用于推送）：

🔥 #1 [标题] | XX.X分 | [链接]
[一句话推荐理由]

🔥 #2 [标题] | XX.X分 | [链接]
...
```

### 7. 边界情况

- **付费墙/仅摘要**：评分时标注"⚠️ 仅摘要评分，建议阅读全文后复核"
- **文章图片多文字少**：按文字部分评分，标注"⚠️ 图文为主，文字部分有限"
- **总分相同**：按深度分降序，深度也相同按原创性
- **用户追问"为什么打这个分"**：展开该篇文章各维度的详细依据（不限字数，完整分析）
- **用户纠正"我觉得这篇文章没那么好"**：接受纠正，记录偏好，后续类似风格文章降低深度分1档
- **用户纠正"这篇应该更高分"**：询问纠正原因并记录，后续同类文章调整评判基准
- **用户只想要评级不想要详情**：只输出等级和总分，省略评分卡片

### 8. 校准（可选，长记忆）

如果用户多次纠正，可以创建或更新项目同级目录下的 `CALIBRATION.md`，记录用户偏好的评分倾向，后续评分时加载参考。

## 示例：一篇典型评分

> 被评文章：《从零实现一个Transformer：完整代码与数学推导》
> 
> 正文摘要：文章手写了完整的Transformer训练代码（约800行），从Self-Attention的数学公式推导开始，逐步实现Multi-Head Attention、Position Encoding、Feed-Forward Network，最后在WMT数据集上训练并对比了BLEU分数。作者提供了Colab Notebook和GitHub仓库。

```
📄 从零实现一个Transformer：完整代码与数学推导
类型: 技术教程

深度   90/100 · 从数学推导到代码实现+实验对比，论证完整
原创性 80/100 · 经典题材但有自己的实现风格和注释体系
实操性 95/100 · 800行完整代码+Colab+GitHub，直接可复现
标题质量 85/100 · 准确无夸张，但"完整"二字略有重复
---
总分 88.3 | A级 🔥
```

> 依据说明（供参考）：
> - 深度打90而不是100，因为Transformer是经典结构，没有提出新的改进方法
> - 原创性打80，同类tutorial很多但有独立实现风格，不算原创研究但也不抄
> - 实操性95给了几乎满分，因为所有代码+环境都可用
> - 标题85，扣分点在于"完整实现"和"完整代码"语义重复
