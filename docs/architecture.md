# SignalFlow 系统架构

## 架构概览

```
                     ┌─────────────────────────────────────────┐
                     │           crontab 定时触发               │
                     │  08:00 日报  │  12:30 知乎荐读          │
                     └────────┬─────────────────┬──────────────┘
                              ▼                 ▼
                     ┌──────────────┐  ┌────────────────┐
                     │ generate.sh  │  │ zhihu-recommend │
                     │   (主入口)    │  │   .sh (次入口)   │
                     └──────┬───────┘  └────────┬───────┘
                            ▼                    ▼
```

## 三层信源架构

### 第 1 层：RSS 固定源
**稳定性高 / 高信噪比 / 主力素材**

| 源 | 权重 | 类型 | 说明 |
|----|------|------|------|
| iThome | P0 | RSS | 台湾繁体 IT 媒体，AI 覆盖全面 |
| VentureBeat AI | P0 | RSS | 英文 AI 深度报道 |
| 橘鸦 | P0 | RSS/Web | AI 精选博客聚合 |
| BestBlogs | P1 | RSS | 中文 AI 独立博客精选 |
| InfoQ 中国 | P1 | RSS | 技术社区新闻 |
| 36氪 | P1 | RSS | 创业/投融资 |
| Qwen Blog | P1 | RSS | 通义千问官方技术博客 |

> 实际运行的信源配置通过 `sources.json` 管理，公开仓库仅展示脱敏架构。

### 第 2 层：知乎开放平台
**实时全网 / 覆盖 RSS 盲区**

- `global_search`：每日 5 组定向查询（模型发布/投融资/头部动态/安全/开源）
- `search_db=realtime` 模式

### 第 3 层：知乎热榜 + 直答
**社区热度信号 + 事实核实**

- `hot_list`：30 条热榜 → AI 关键词过滤
- `zhida`：对🔥新闻做 one-shot 事实核实

## 评分系统

### 质量评分（四维体系）

```
total = depth × 0.35 + originality × 0.25 + practicality × 0.25 + title_quality × 0.15
```

- `score ≥ 75` → A 级 ✅ 优先推送
- `score ≥ 60` → B 级 🔔 可参考
- `score < 60` → C 级 ❌ 过滤

### 四维评分（知乎文章，`skills/article-rating/`）

```
总分 = 深度×0.35 + 原创性×0.25 + 实操性×0.25 + 标题质量×0.15
```

- `总分 ≥ 75` → A 级，推送
- `总分 ≥ 60` → B 级，备选
- `总分 < 60` → C 级，不推送

## 事件追踪

事件状态机：`active → cooling → closed`

- 🔥 新闻自动入库
- 连续报 → 更新状态
- 收尾 → 标记「已完结」
- 超过 3 天连续 → 自动生成时间线

## 推送

当前通过 QQ 开放平台 Bot 推送。  
后续计划支持：Telegram / Discord / Email。

## 数据流

```
抓取 → 质量评分 → 去重 → 事件匹配 → 报告生成 → 推送 → 日志归档
```

## 技术约束

- 知乎 API 免费版：每日 1000 次调用
- 日报 + 荐读合计使用不超过 20 次
- 抓取源超时限制：每个源最长 15 秒
- 失败容错：单源失败不影响整体，连续 2 天触发告警
